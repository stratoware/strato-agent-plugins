# Shared sync workflow

Use this workflow for design and verification sync. Keep findings, questions, decisions, and plans in chat. Use compact tables for comparisons and proposed actions, with Strato IDs or short finding IDs so the user can refer to rows.

## Establish the baseline

Discover the connected MCP capabilities and product, using existing project context where unambiguous. Compare current Strato records with the current folder, working changes, and supplied materials. Follow pagination and explain missing or unreadable evidence that limits the comparison.

Use `.strato/sync-history.json`, a JSON list of sync events, to see whether Strato changes have been made before. Missing or empty history means first sync; existing history does not establish that either the design or verification baseline is complete. Choose the work from current evidence, including useful records already in Strato.

On first sync, take ownership of proposing a coherent baseline, including improvements to existing content and organization. Reuse what fits and recommend rewriting, splitting, consolidating, or moving records where justified. Preserve supported intent and traceability.

## Interview and agree the plan

Lead the user through unresolved questions in small, focused rounds. Use previous answers and available evidence, explain why each answer matters, and recommend an answer where supported. Ask for missing inputs early, continuing supported analysis while waiting. Continue until the planned work is clear or the user explicitly defers an area.

Use native Plan mode if the client provides an allowed way to enter it; otherwise conduct the same interview and planning in chat. Answers inform the plan; they are not instructions to write each decision immediately.

Present the proposed updates and folder structure for confirmation, including changes to existing records, local files, and any deferred work. Summarize large inventories by logical group, showing individual details where needed for a decision or when requested. An already approved plan or concrete edit needs no repeat approval.

## Complete the selected work

Continue ready, authorized work through readback and reconciliation. Distinguish completion of the selected work from completeness of the product baseline: a successful batch or folder structure does not establish substantive coverage. Assess remaining gaps against the intended baseline and evidence, and explain unassessed areas in chat.

When broader work needs input or selection, offer two or three concrete next steps and recommend one, explaining what each will produce and what input it needs. Prioritize substantive gaps over further scaffolding. A narrow task can be complete with wider gaps disclosed; do not expand the user's scope or invent content to fill a tree.
